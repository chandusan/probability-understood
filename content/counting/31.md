# Build a count through many stages

A multistage count is a tree of decisions. The product rule works when every partial path of the same length has the same number of ways to take the next step. It counts the final outcomes by counting branches, layer after layer.

## Rule 3: extend the two-stage product

Let $n_1$ be the number of first-stage choices. For each $i=2,\ldots,k$, let $n_i$ be the number of choices at stage $i$ after any valid sequence of the preceding $i-1$ choices. If this count is fixed at each stage, then

$$
\boxed{N=n_1n_2\cdots n_k.}
$$

There are $n_1$ partial outcomes after one stage. Each gives $n_2$ outcomes after the next stage, so there are $n_1n_2$. Each of those gives $n_3$ after stage 3, and so on.

## The choices can depend on earlier choices

For a three-person podium from seven runners, the choices are $7,6,5$. The identities of the remaining runners change with the earlier winners, but the number available is always six at stage 2 and five at stage 3. Therefore $7\times6\times5=210$.

The rule does **not** require the same menu of choices on every branch. It requires the same number of choices, together with a construction that represents each outcome exactly once.

This is also why multiplying branch counts is not the same as assuming probabilistic independence. Sampling without replacement has dependent selections, yet the product count is perfectly valid.

## Constraints can break the regular tree

Suppose a code has three positions drawn without replacement from $A,B,C$, with the rule that the first position is $A$ or $B$ and the second position is not $C$.

If the first position is $A$, the second must be $B$, then the third is $C$. If the first is $B$, the second must be $A$, then the third is $C$. The stage counts are $2,1,1$, giving two codes.

For a more complicated constraint, different branches may allow different numbers of completions. Then split into cases or count unrestricted outcomes and subtract forbidden ones, as in the feature-pipeline exercise.

## Check your understanding

A four-character code uses the letters $A,B,C,D,E$. Letters may repeat, but consecutive characters cannot match. How many codes are possible?

<details markdown="1"><summary>Reveal the branch counts</summary>

There are five choices for the first character. At each later stage, exactly one letter—the immediately preceding one—is prohibited, leaving four choices:

$$
5\times4\times4\times4=320.
$$

A letter used earlier can reappear if it is not the immediately preceding letter. Thus $ABAB$ is allowed. Counting $5\times4\times3\times2$ would impose a stronger no-repetition rule that the question did not specify.
