# Nothing qualifies—or everything does

Two events sit at the extremes of every event system. The empty event accepts no outcome. The entire sample space accepts every outcome the model allows.

## The empty event

The empty set is written

$$
\varnothing=\{\}.
$$

It has no elements. In a one-die model, “the result is both less than 2 and greater than 5” selects no face, so it defines $\varnothing$.

The empty event never occurs: there is no outcome that could make its membership test succeed. Its probability is

$$
P(\varnothing)=0.
$$

Do not confuse $\varnothing$ with $\{0\}$. The latter contains one element, the number zero. Whether zero is a possible outcome depends on the experiment.

## The entire event

The event $S$ contains every possible outcome. Every trial modeled by $S$ therefore makes $S$ occur, and

$$
P(S)=1.
$$

For a standard die, “the result is one of 1,2,3,4,5,6” is certain within the model. Model-based certainty does not mean a real apparatus cannot malfunction; it means that malfunction was not included among the specified outcomes.

<details markdown="1"><summary>Why must the empty event have probability zero?</summary>

Adding an empty event to $S$ changes nothing: $S\cup\varnothing=S$. The two sets are disjoint. Additivity and normalization give

$$
1=P(S)=P(S)+P(\varnothing)=1+P(\varnothing).
$$

Subtracting 1 yields $P(\varnothing)=0$. We will formally introduce these probability axioms later.

</details>

## Zero probability does not always mean empty

Return to the continuous uniform-angle example. Every exact angle has zero interval width, so

$$
P(\theta=30^\circ)=0.
$$

But the event $\{\theta=30^\circ\}$ is not empty. It contains that possible exact angle. In continuous models, zero-probability events need not be impossible; likewise, a probability-one event need not contain every possible outcome.

The empty event is always impossible within the model. The reverse inference from “probability zero” to “empty” requires extra conditions, such as a finite sample space in which every outcome has positive probability.

## A useful filtering analogy

A database query whose conditions cannot jointly be satisfied returns no rows. That is an empty result set, much like an empty event. It is different from a missing value or SQL `NULL`: there are zero matching records, rather than a record with an unknown field.

## Check your understanding

Choose $X$ uniformly from $[0,1]$. Are the events $\{X=1/2\}$ and $\varnothing$ the same because both have probability zero?

<details markdown="1"><summary>Reveal the distinction</summary>

No. The first contains one possible outcome; the second contains none. They have the same probability under this model but different members. Equality of probabilities does not imply equality of events.

</details>
